# 배포각 — 첫삽부터 배포까지

**배포각은 배포 전날 여는 게 아니라, 첫 삽 뜰 때부터 여는 것이다.**

"배포 후 참교육 당하는" 12가지 함정(데이터 날림·돈 계산 오류·권한 뚫림·카톡 공유 안 뜸 등)은 배포 직전에 발견하면 이미 재작업이다. 대부분은 **기획·와이어프레임 때 미리 정해두면 공짜**다. 이 스킬은 그 12개를 두 시점에 건다.

## 먼저 — 지금 어느 국면인가

- 아직 **코드가 거의 없고 아이디어·기획 단계**다(또는 사용자가 "만들려는데", "와이어프레임", "기획", "첫삽"이라 함) → **A. 첫삽 모드**로 간다.
- 이미 **코드가 있고 배포를 앞뒀다**(또는 "배포 전 점검", "배포해도 되나"라 함) → **B. 배포점검 모드**로 간다.
- 헷갈리면 프로젝트에 실제 소스가 있는지 한 번 보고 판단하되, 애매하면 사용자에게 한 줄로 물어본다.

같은 팩 루트의 `snippets/`(코드 조각)와 `recipes/`(레시피)를 참고 자료로 쓴다.

---

## A. 첫삽 모드 — 만들기 전 (와이어프레임 + 함정 스코핑)

목표: 화면을 먼저 눈으로 보고, **이 서비스에 12개 함정 중 뭐가 걸리는지** 골라서, 코드 짜기 전에 "처음부터 이렇게 설계하라"를 손에 쥐여준다.

### 1) 스코핑 — 여섯 가지만 파악한다(아이디어에서 추론, 모르면 물어봄)

사용자가 이미 말한 건 되묻지 말고 추론한다.

- **저장/어드민이 있나?** (관리자가 뭔가 입력·수정·삭제) → 걸리는 함정: ①백업 ②소프트삭제 ③서버권한 ④키 환경변수
- **돈을 다루나?** (가격·결제·할인·정산) → ⑧금액 정수 (+결제 연동이면 ⑤도)
- **외부 서비스에 연동하나?** (결제·문자·이메일·로그인·검색·지도 API) → ⑤재시도·타임아웃·멱등성 ⑥로그
- **남에게 공유·검색되나?** (랜딩·마케팅·카톡 공유·구글 노출) → ⑨OG ⑩제목·설명·lang·favicon ⑪robots/sitemap ⑫GEO
- **사용자가 글/폼을 입력하나?** → 0b 입력값 검증·이스케이프(XSS)
- **날짜·시간을 보여주나?** → ⑦UTC 저장·한국시간 표시
- (항상) 비밀키·비밀번호 깃 유출 금지 → 0a 보안

### 2) 와이어프레임 — 정적 HTML 한 파일로 뽑는다

- 스코핑 결과를 반영해 **의존성 없는 정적 HTML 한 파일**로 저화질 와이어프레임을 만든다(회색 박스·플레이스홀더 텍스트 수준, 예쁘게 X). 주요 화면(홈·목록·상세·어드민 등)을 한 페이지에 섹션으로 나열해도 된다.
- 모바일·PC 둘 다 안 깨지게 최소한의 반응형(`recipes/모바일-안깨지게.md` 원칙)만 넣는다.
- 파일로 저장하고 사용자가 브라우저로 열어보게 절대경로를 알려준다. **먼저 이 시안에 합의**한 뒤 다음으로 넘어간다(시안먼저 원칙).

### 3) 설계 지시서 — "너는 이게 걸린다"

와이어프레임과 함께, 스코핑에서 걸린 함정만 추려 **코드 짜기 전에 반영할 설계 지침**으로 정리한다. 비개발자도 알게 "왜 → 안 하면 → 어떻게" 한 줄씩. 각 항목은 배포점검(B)의 같은 번호와 `snippets/`를 가리킨다.

예: "어드민에서 글을 저장·삭제 → ①저장은 덮어쓰기 전 백업(save-with-backup) ②삭제는 소프트삭제(soft-delete) ③저장·삭제 권한은 서버 API에서 검사. 지금 데이터 모델에 `deleted_at`·`updated_at` 칸부터 넣고 시작해라."

이걸로 사용자는 커서·러버블·Claude에 "이 설계대로 만들어줘"라고 바로 넘길 수 있다.

## B. 배포점검 모드 — 다 만든 뒤 (12항목 점검·수정)

이 프로젝트를 실제 배포하기 전에, 아래 12가지를 **코드를 실제로 읽어** 점검하고 체크리스트로 보고한 뒤, 동의를 받아 빠진 것을 **최소 수정**으로 고친다.

1. 프로젝트 구조를 파악한다(정적 HTML / Next.js 등, 데이터 저장 방식, 외부 API, 어드민 유무).
2. 아래 항목을 각각 **✅적용됨 / ⚠️부실 / ❌없음 / — 해당없음**으로 판정하고 근거(파일:줄)를 단다.
3. 위험도(높음/중간/낮음)와 함께 체크리스트로 보고한다.
4. 고칠 것을 우선순위로 제시하고, 동의를 받아 최소 수정으로 고친다(과설계 금지). 비밀·키를 코드에 넣지 않는다.

### 점검 항목

**⚠️ 배포 전 필수 보안 (먼저)**
0a. 비밀키·비밀번호가 코드나 커밋에 노출됐는지, `.env`가 `.gitignore`에 있는지 (`recipes/키-깃허브에-올리지마.md`)
0b. 사용자 입력을 서버에서 검증하고 화면 출력 시 이스케이프하는지(XSS·조작 방지) (`recipes/입력값-검증.md`)

**데이터**
1. 백업 없이 통째 덮어쓰기 → 저장 직전 타임스탬프 백업 (`snippets/js/save-with-backup.ts`)
2. 물리삭제 → `deleted_at` 소프트삭제 (`snippets/js/soft-delete.ts`)

**보안**
3. 권한 검사를 프론트에만 두는지 → 서버 API에서 재검증
4. 비밀번호·키 하드코딩/기본값 폴백 → 환경변수 + fail-closed (`snippets/js/require-env-secret.ts`)

**외부 연동**
5. 외부 API 재시도·타임아웃·멱등성·부분성공 (`snippets/js/fetch-with-retry.ts`)

**운영**
6. 에러 로그 + 돈 변경 감사로그 (`snippets/js/log.ts`)
7. 시간 UTC 저장·한국시간 표시 (`snippets/js/kst-time.ts`)
8. 금액 정수 계산(float 금지) (`snippets/js/money.ts`)

**공유·검색**
9. OG 태그(og:title/description/image/url) — 카톡 공유 미리보기 (`snippets/seo/`)
10. 페이지 제목 + meta description + `lang="ko"` + favicon (기본값 "Create Next App" 방치 확인)
11. robots.txt + sitemap.xml
12. GEO — JSON-LD 구조화 데이터

## 원칙 (두 모드 공통)
- 최소 수정, 과설계 금지. 이미 잘 된 항목은 그대로 둔다.
- 각 항목의 "왜"를 한 줄로 설명한다(비개발자 대상).
- 첫삽 모드는 "미리 심을 설계"로, 배포점검 모드는 "고친 내용 요약"으로 끝맺는다.

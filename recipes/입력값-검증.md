# 사용자 입력을 믿지 마세요 (검증·이스케이프)

폼·검색창·URL로 들어오는 값은 **전부 공격일 수 있다고 가정**하세요.
바이브코딩으로 만든 사이트는 입력값을 그대로 저장·표시하는 경우가 많은데, 여기서 두 가지가 터집니다.

## 1. 화면에 그대로 뿌리면 → XSS

사용자가 이름 칸에 `<script>...</script>`를 넣었는데 그걸 화면에 그대로 출력하면, 그 스크립트가 **다른 방문자 브라우저에서 실행**됩니다(계정 탈취 등).

- **React·Vue·Svelte 쓰면** 대부분 자동으로 이스케이프됩니다(그냥 `{값}`으로 쓰면 안전). **`dangerouslySetInnerHTML` / `v-html` / `innerHTML`만 조심**하세요 — 이게 자동 방어를 끄는 스위치입니다.
- **순수 HTML/JS면** `element.textContent = 값` 을 쓰세요. `innerHTML = 값` 은 위험.

## 2. 서버가 "이 값이 맞나" 안 보면 → 쓰레기·조작 데이터

프론트에서 "필수 입력"을 검사해도, 사용자는 서버 API를 직접 부를 수 있습니다([권한과 같은 원리](../README.md)).
그래서 **서버에서도** 값을 검증해야 합니다:

- 필수값이 실제로 있나, 타입이 맞나(숫자 칸에 글자?)
- 길이 제한(이름 10000자 붙여넣기 방지), 이메일 형식 등
- 금액·수량 같은 건 **음수·이상값**이 안 들어오는지

```js
// 서버 API에서, 저장하기 전에
if (typeof name !== "string" || name.length === 0 || name.length > 100) {
  return res.status(400).json({ error: "이름을 확인해주세요" });
}
const price = Number(body.price);
if (!Number.isInteger(price) || price < 0) {
  return res.status(400).json({ error: "금액이 올바르지 않습니다" });
}
```

## (참고) 공개 API는 남용도 막으세요

로그인 없이 누구나 부를 수 있는 API(검색·조회 등)는, 봇이 초당 수백 번 때리면 외부 API 쿼터·요금이 샙니다.
간단하게는 **IP당 분당 요청 수 제한**(rate limit)을 두세요. 트래픽이 커지기 전엔 이 정도면 충분합니다.

> 규칙 하나만 기억하면 됩니다: **"프론트 검증은 편의, 진짜 방어는 서버."**

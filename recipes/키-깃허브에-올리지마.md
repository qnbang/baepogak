# 비밀키를 깃허브에 올리지 마세요 (초보자 1순위 사고)

바이브코딩 초보자가 가장 많이, 가장 크게 당하는 사고입니다.
API 키·비밀번호가 든 파일을 실수로 깃허브에 올리면 → **봇이 몇 분 안에 긁어가서** 요금 폭탄(특히 클라우드·결제 키)이나 계정 탈취로 이어집니다.

## 지키는 법 (3가지면 끝)

**1. 비밀값은 `.env` 파일에만 두기**
코드에 `const KEY = "sk-abc123..."` 처럼 직접 쓰지 말고, `.env` 파일에 넣고 코드에선 `process.env.KEY`로 읽으세요.

**2. `.env`를 `.gitignore`에 넣기 (이게 핵심)**
`.gitignore` 파일에 아래를 넣으면 깃이 `.env`를 아예 안 올립니다:
```
.env
.env.local
*.key
*-key.json
```
(이 저장소의 [.gitignore](../.gitignore)를 그대로 복사해 쓰세요.)

**3. `.env.example`로 "이름만" 공유**
남들은 어떤 키가 필요한지 알아야 하니, 값은 빈 칸으로 둔 [.env.example](../.env.example)만 올리세요.

## 배포처(Vercel 등)에는 따로 넣어야 합니다

흔한 실수: `.env`를 안 올렸더니 **배포한 사이트에서 키가 없어서 안 돌아감**.
`.env`는 내 컴퓨터에만 있는 거라, 배포처에는 **그쪽 설정 화면에서 환경변수를 따로 등록**해야 합니다.
- Vercel: 프로젝트 → Settings → Environment Variables
- 등록 후 **재배포**해야 적용됩니다.

## 이미 올려버렸다면? (빨리)

1. **키를 즉시 폐기하고 새로 발급**하세요. (깃 기록에서 지워도 이미 노출된 키는 죽은 겁니다 — 무조건 재발급)
2. 그다음 기록에서 제거: `git rm --cached .env` → `.gitignore`에 추가 → 커밋.
3. 공개 저장소였다면 이미 봇이 봤다고 가정하세요. 재발급이 유일한 안전책입니다.
